In-Context Weights上下文里的权重

An LLM that runs other LLMs from its prompt.一个从 prompt 里运行其他 LLM 的 LLM。

A GPU runs whatever model is loaded into its memory. This transformer does the same with its prompt: with the weights of GPT-2 XL or Llama-3.2-3B in its prompt, it writes the text that model writes. Its own weights come from a program that Claude wrote.

GPU 会运行装进它显存里的任何模型。这个 transformer 对它的 prompt 做同样的事：把 GPT-2 XL 或 Llama-3.2-3B 的权重放进它的 prompt，它写出的就是那个模型会写出的文字。它自己的权重来自 Claude 写的一个程序。

Xingyu Dang党星宇 · experiment log实验日志

TL;DR

We built an ordinary GPT-2-architecture transformer (softmax attention, LayerNorm, GELU) and call it the interpreter. Its weights are written by a program. Its prompt holds a second language model: each row of each weight matrix of that model takes one position (792,931 positions for GPT-2 XL), and the text follows. At every position of the text, the interpreter outputs the token that the model in its prompt predicts.

我们造了一个普通的 GPT-2 架构的 transformer（softmax 注意力、LayerNorm、GELU），下文称它为解释器。它的权重由程序写出。它的 prompt 里放着第二个语言模型：那个模型每个权重矩阵的每一行占一个位置（GPT-2 XL 共 792,931 个位置），文本跟在后面。在文本的每个位置上，解释器输出的就是 prompt 里的模型所预测的 token。

The interpreter's weights depend only on the shape of the model in the prompt (width, depth, heads, vocabulary). One set of weights runs GPT-2, GPT-2 Medium, Large and XL, and for each of them all 1,024 next tokens of a text match. Its logits agree with a float64 run of the model to 9 to 11 digits; ordinary float32 inference agrees to 3 or 4. A second interpreter, built from the same GPT-2 parts, runs the Llama family. The largest model we have put in the prompt is Llama-3.2-3B (3.2 billion parameters, 1,031,025 prompt positions): the first 40 tokens it generates through the interpreter equal those of the model run directly.

解释器的权重只取决于 prompt 里的模型的形状（宽度、层数、头数、词表）。同一套权重运行 GPT-2、GPT-2 Medium、Large 和 XL，每个模型在一段文本上的 1,024 个下一个 token 全部一致。它的 logits 与该模型 float64 运行的结果对上 9 到 11 位；普通 float32 推理只对上 3 到 4 位。第二个解释器用同样的 GPT-2 零件搭成，运行 Llama 家族。我们装进 prompt 的最大模型是 Llama-3.2-3B（3.2B 参数，占 1,031,025 个 prompt 位置）：通过解释器生成的前 40 个 token 与直接运行该模型的结果相同。

The model is part of the input, so an operation on a model's weights becomes an operation on a prompt. Changing 768 numbers of the prompt steers GPT-2 toward a topic. Swapping the weights in the prompt before every token lets two models write one text in turns. Gradient descent on the prompt trains the model that is in it.

模型是输入的一部分，所以对模型权重做的操作就变成了对 prompt 做的操作。改动 prompt 里的 768 个数，就能把 GPT-2 引向某个话题。在每个 token 之前更换 prompt 里的权重，两个模型就能轮流写同一段文字。对 prompt 做梯度下降，训练的就是 prompt 里的那个模型。

What the interpreter reads解释器读的是什么

The interpreter's input is one sequence. The weights of the model to run come first, as real-valued vectors, one matrix row per position. The text comes after them as ordinary tokens. Figure 1 shows the arrangement.

解释器的输入是一个序列。前面是要运行的那个模型的权重，以实数向量的形式给出，每个位置放矩阵的一行；后面是文本，就是普通的 token。图 1 画出了这个安排。

The interpreter's own weights contain nothing about the model in the prompt beyond its shape. Figure 2 draws the input for GPT-2 XL to scale: the text is the last 0.13% of it.

解释器自己的权重里，除了形状之外没有任何关于 prompt 里那个模型的信息。图 2 按比例画出了 GPT-2 XL 对应的输入：文本只占最后 0.13%。

The interpreter is a standard checkpoint. Exported as a transformers.GPT2LMHeadModel, it loads with from_pretrained and runs with stock code; the weights of the model to run go in as inputs_embeds (experiment log).

解释器是一个标准的检查点。把它导出成 transformers.GPT2LMHeadModel，用 from_pretrained 就能加载，用原装代码就能运行；要运行的模型的权重作为 inputs_embeds 输入（见实验日志）。

Agreement with the model run directly与直接运行该模型的结果有多一致

For each model we take the first 1,024 tokens of Alice in Wonderland. We run the model directly in float64, and we run the interpreter with that model in its prompt. Then we compare the next token at every position and the logits over the whole vocabulary. Every next token matches for every model in Figure 3. The logits agree to 9 to 11 digits, closer than float32 inference of the same model comes to its own float64 run.

对每个模型，我们取《爱丽丝漫游奇境》的前 1,024 个 token，一边在 float64 下直接运行这个模型，一边把它放进解释器的 prompt 来运行，然后比较每个位置上的下一个 token，以及整个词表上的 logits。图 3 里的每个模型，下一个 token 全部一致。logits 对上 9 到 11 位，比同一个模型的 float32 推理与它自己的 float64 结果之间还要接近。

The Llama family uses parts that GPT-2 does not have: RMSNorm, rotary positions, grouped-query attention and a SwiGLU MLP whose gate is SiLU. The second interpreter builds each of them from LayerNorm, softmax attention and GELU, so an architecture from 2019 runs models released in 2024. The largest model we have put in the prompt is Llama-3.2-3B (3.2 billion parameters, 1,031,025 prompt positions): the first 40 tokens it generates through the interpreter equal those of the model run directly.

Llama 家族用到了 GPT-2 没有的部件：RMSNorm、旋转位置编码、分组查询注意力，以及门控为 SiLU 的 SwiGLU MLP。第二个解释器用 LayerNorm、softmax 注意力和 GELU 把它们一一搭出来，于是一个 2019 年的架构运行起了 2024 年发布的模型。我们装进 prompt 的最大模型是 Llama-3.2-3B（3.2B 参数，占 1,031,025 个 prompt 位置）：通过解释器生成的前 40 个 token 与直接运行该模型的结果相同。

Generating text生成文本

The interpreter also generates. The token it outputs at the last position is appended to its input, and the loop uses only the interpreter and its prompt. The prompt's keys and values are computed once, and the text positions use an ordinary key-value cache; one token of GPT-2 XL then takes about 2 seconds on two B200 GPUs. All generation in this post is greedy decoding unless a figure says otherwise, and every run is compared with the same model decoding greedily in float64.

解释器也能自己生成。它在最后一个位置输出的 token 被接到输入后面，这个循环只用到解释器和它的 prompt。prompt 的 key 和 value 只算一次，文本位置使用普通的 KV 缓存；这样 GPT-2 XL 的一个 token 在两张 B200 上大约需要 2 秒。除非图中另有说明，本文的生成都是贪心解码，每次运行都与同一个模型在 float64 下贪心解码的结果相比较。

Can a reasoning model think inside it?推理模型能在它里面思考吗？

Yes. DeepSeek-R1-Distill-Qwen-1.5B, a model trained to reason step by step before it answers, goes into the prompt (949,361 positions). The interpreter writes its chain of thought and then its answer, 220 / 220 tokens equal to the model run directly.

可以。DeepSeek-R1-Distill-Qwen-1.5B 是一个被训练成先逐步推理再回答的模型，把它装进 prompt（949,361 个位置）。解释器写出它的思考过程，然后写出答案，220 / 220 个 token 与直接运行该模型一致。

Also in the experiment log: a coding model writes a complete function; answers in Chinese and French; a chat with Qwen2.5-0.5B.

实验日志里还有：代码模型写出一个完整的函数；中文和法语的回答；和 Qwen2.5-0.5B 聊天。

One interpreter, different models in its prompt同一个解释器，prompt 里放不同的模型

Once the shape is chosen, the interpreter's weights are fixed. Which model runs is decided by the prompt alone, so the model can be exchanged between runs, between the turns of a conversation, or between two tokens.

形状一旦选定，解释器的权重就固定了。运行哪个模型完全由 prompt 决定，所以可以在两次运行之间、一段对话的两轮之间、甚至两个 token 之间更换模型。

Can the model be upgraded by changing the prompt?换一下 prompt 就能给模型升级吗？

Yes. One interpreter, written for GPT-2 XL's shape, stays as it is (the checksum of its weights is the same in every run); the prompt holds GPT-2, then GPT-2 Medium, Large and XL, and the interpreter writes what each of them writes. On the first question the smallest model names the wrong city; the larger ones answer Rome.

可以。一个按 GPT-2 XL 的形状写出的解释器保持不变（每次运行的权重校验码都相同）；prompt 里依次装进 GPT-2、GPT-2 Medium、Large 和 XL，解释器写出的就是它们各自写出的内容。第一个问题上，最小的模型答错了城市，更大的几个都答 Rome。

Can two models write one text, taking turns token by token?两个模型能逐 token 轮流写同一段文字吗？

Yes. The weights in the prompt are swapped before every token: odd tokens are written with Qwen2.5-0.5B-Instruct in the prompt, even tokens with Qwen2.5-Coder-0.5B-Instruct, each reading everything written so far. Every token is the one its writer would choose when run directly (56 of 56).

可以。每写一个 token 之前都把 prompt 里的权重换掉：奇数 token 由 Qwen2.5-0.5B-Instruct 写，偶数 token 由 Qwen2.5-Coder-0.5B-Instruct 写，每个模型都读到目前为止写出的全部内容。每个 token 都是轮到的那个模型直接运行时会选的（56 / 56）。

What does a training run look like from inside the interpreter?从解释器里看，一次训练是什么样子？

We saved a character model (217,728 parameters, TinyStories) at 27 points of its training and loaded the saved models into the same interpreter one after another. Read the rows from top to bottom: the same interpreter, with the same weights of its own, writes noise, then “the the the”, then stories. At every point its text and its held-out loss equal those of the saved model run directly (largest logit difference 9.7×10-12).

我们在一个字符模型（217,728 个参数，TinyStories）训练过程中的 27 个时刻各存一份，再把这些存档依次装进同一个解释器。从上往下看：同一个解释器、它自己的权重始终不变，先写出乱码，然后是“the the the”，最后是故事。每一个时刻，它写出的文字和留出 loss 都与直接运行那份存档相同（logits 最大差 9.7×10-12）。

Also in the experiment log: two chat models in conversation through one interpreter; eight models in one batch.

实验日志里还有：两个对话模型通过同一个解释器对话；一个 batch 里八个模型。

Editing the model by editing the prompt改 prompt 就是改模型

A weight of the model in the prompt is a number at a known position of the input. An operation on the weights is therefore an operation on the input. In each experiment below, the interpreter's output is compared with the same operation applied to the model itself.

prompt 里那个模型的每个权重，都是输入里某个已知位置上的一个数。所以对权重做的操作就是对输入做的操作。下面每个实验里，解释器的输出都与直接对模型做同样操作的结果相比较。

Can the model be steered by editing a few hundred numbers of the prompt?改 prompt 里的几百个数，就能操纵模型的话题吗？

Yes. A steering vector, the difference between the model's internal state on “ocean” and on “desert”, is added to one bias of GPT-2. In the prompt that is a change at 768 of 184,531 positions, one number at each. The same start then continues differently, and the interpreter writes what the steered model writes (24 / 24 tokens).

可以。把一个 steering 向量（模型在“ocean”和“desert”上的内部状态之差）加到 GPT-2 的一个偏置上。在 prompt 里，这只是 184,531 个位置中 768 个位置的改动，每个位置改一个数。同样的开头于是接出了不同的内容，解释器写出的就是被操纵后的模型写出的内容（24 / 24 个 token）。

Can interpretability experiments be run by editing the prompt?能不能通过改 prompt 来做可解释性实验？

The attention heads here are GPT-2's own, and GPT-2 is in the prompt. A head computes its value vectors with a weight matrix of 64 rows (its part of GPT-2's value projection), and each of those rows is one position of the prompt. Setting those 64 positions to zero makes the head's value vectors zero at every token, which switches the head off. Removing a layer is setting the 1,536 rows of its two output matrices to zero. On an indirect-object task (8 prompts such as “When Mary and John went to the store, John gave a drink to”) we measured the logit of the right name minus that of the wrong one under 16 such edits of GPT-2. The interpreter's logits equal those of the edited model run directly (largest difference 3.8×10-7). What the measurements say: zeroing the three name-mover heads of Wang et al. (2022) leaves the difference almost unchanged (3.07 to 3.13; that paper reports the same under its mean ablation, and describes eight backup heads that take over). With the eight backup heads zeroed as well (11 heads, 704 positions) it falls to 1.43. Removing layer 0 reverses the sign (-0.36), and removing the last layer doubles it (6.47).

这里说的注意力头是 GPT-2 自己的头，而 GPT-2 在 prompt 里。一个头用一个 64 行的权重矩阵（GPT-2 的 value 投影矩阵中属于它的那部分）来计算 value 向量，这 64 行各占 prompt 的一个位置。把这 64 个位置置零，这个头在每个 token 上算出的 value 向量就都是零，也就等于把它关掉了。去掉一层，则是把它两个输出矩阵的 1,536 行置零。在间接宾语任务上（8 条形如 “When Mary and John went to the store, John gave a drink to” 的 prompt），我们对 GPT-2 做了 16 种这样的编辑，测量正确名字与错误名字的 logit 之差。解释器的 logits 与直接运行编辑后模型的结果一致（最大差 3.8×10-7）。测量结果本身：把 Wang 等（2022）的三个 name mover 头置零，差值几乎不变（3.07 到 3.13；该论文在均值消融下报告了同样的现象，并描述了会接替它们的八个 backup 头）。把八个 backup 头也一起置零（共 11 个头、704 个位置）后，差值降到 1.43。去掉第 0 层会使差值变号（-0.36）；去掉最后一层则使它翻倍（6.47）。

Can the model in the prompt be trained by backpropagating through the interpreter?能不能把梯度穿过解释器反传回去，训练 prompt 里的模型？

Yes. The interpreter stays frozen. The loss is its own next-character loss; backpropagation runs through its 20 layers into its input, and the gradient that arrives at the prompt positions, divided by each row's scale, is the gradient of the weights of the model in the prompt. At random initial weights it agrees with the model's own gradient to a relative error of 5.0×10-11. We then trained the same 93,936-parameter character model twice, from the same start and on the same batches: once using only gradients that came through the interpreter, once directly. After 3,000 steps the held-out losses differ by at most 9.4×10-11, and the two models write the same text. One caveat: the agreement is per step. In an earlier run that was unstable in itself (large initial weights; its held-out loss fell to 2.3 and then climbed to 5.3), the two trajectories drifted apart, to 5% in the weights after 4,000 steps, while every gradient still agreed to 5.7×10-11.

可以。解释器保持冻结。loss 就是它自己的下一个字符的 loss；反向传播穿过它的 20 层一直到输入，到达 prompt 位置的梯度除以每一行的尺度，就是 prompt 里那个模型的权重的梯度。在随机初始权重处，它与模型自己的梯度相对误差为 5.0×10-11。然后我们把同一个 93,936 参数的字符模型从同一个起点、用同样的 batch 训练了两次：一次只用穿过解释器得到的梯度，一次直接训练。3,000 步之后，两者的留出 loss 最多相差 9.4×10-11，写出的文字也相同。需要说明的一点：一致性是逐步的。在更早的一次本身就不稳定的运行里（初始权重很大，留出 loss 先降到 2.3，之后又升到 5.3），两条轨迹逐渐分开，4,000 步后权重相差 5%，而每一步的梯度仍然吻合到 5.7×10-11。

How many bits per weight does the prompt need?prompt 里每个权重需要多少比特？

The prompt holds the model at whatever precision you give it. We rounded every weight of Qwen2.5-0.5B-Instruct to a few bits and put the rounded model in the prompt. The interpreter runs each rounded model as it is (every token equal to that model run directly), so what changes with the bits is the model, as it would on any hardware. Down to 4 bits the answer does not change; at 3 bits it does.

prompt 里的模型是什么精度，解释器就按什么精度运行它。我们把 Qwen2.5-0.5B-Instruct 的每个权重舍入到若干比特，再把舍入后的模型装进 prompt。解释器如实运行每一个舍入后的模型（每个 token 都与直接运行那个模型一致），所以随比特数变化的是模型本身，在任何硬件上都一样。降到 4 比特，回答都不变；到 3 比特就变了。

Also in the experiment log: a dial between a model and its fine-tune; one fact changed in 768 positions.

实验日志里还有：在一个模型和它的微调版之间连续调节；用 768 个位置改掉一个事实。

Models that draw and control会画画和会控制的模型

The model in the prompt does not have to be a language model. Its tokens can be pixels or motor commands, and its inputs can be real-valued vectors.

prompt 里的模型不必是语言模型。它的 token 可以是像素或控制指令，它的输入也可以是实数向量。

Can it draw?它能画画吗？

Yes. In the prompt we put two small image models, one for digits and one for clothing (about 1.3 million parameters each): each is told what to draw and writes a 28×28 picture one pixel token at a time, 784 tokens, each one of 8 or 16 grey levels. With such a model in its prompt the interpreter drew these 40 pictures of handwritten digits and pieces of clothing. Sampling pixel by pixel with the same random numbers, it chose the same grey level as the image model at 31,360 of 31,360 pixels.

能。我们往 prompt 里装的是两个小的图像模型，一个画数字、一个画服饰（各约 129 万个参数）：告诉它画什么，它就一个像素 token 接一个像素 token 地写出一张 28×28 的图，共 784 个 token，每个 token 是 8或16 个灰度级之一。把这样的模型装进 prompt，解释器画出了下面 40 张手写数字和服饰。逐像素采样、使用相同的随机数时，31,360 个像素里有 31,360 个与图像模型选的灰度相同。

Can it control something?它能控制东西吗？

Yes. The model in the prompt is a small policy (26,176 parameters) for a cart with a pole on it: it reads the cart's recent states as input vectors and writes push left or push right. The interpreter balanced the pole for all 500 steps in each of 3 runs, choosing the policy's own action at every step (1500 of 1500). With random pushes the pole falls after 10 to 28 steps.

能。prompt 里是一个小的策略模型（26,176 个参数），控制一辆顶着杆子的小车：它把小车最近的状态当作输入向量读入，输出“向左推”或“向右推”。在 3 次运行里，解释器每次都把杆子稳住了全部 500 步，每一步选的都是策略模型自己的动作（1500 / 1500）。随机乱推的话，杆子在 10 到 28 步后倒下。

Also in the experiment log: an image classifier, 10,000 of 10,000 test images.

实验日志里还有：图像分类器，10,000 张测试图全部一致。

How the interpreter computes each operation解释器怎样完成每一种运算

Each operation of the model in the prompt is carried out by a part the interpreter already has. Two kinds need a trick: the matrix products, because the matrix is in the prompt and the interpreter's weights know nothing of it, and the normalizations.

prompt 里的模型的每一种运算，都由解释器已有的部件来完成。需要技巧的有两类：矩阵乘法（矩阵在 prompt 里，解释器的权重对它一无所知）和归一化。

A smaller model fits an interpreter written for a larger shape: it is padded with zeros. Missing layers, heads and neurons are zero, and the residual vectors are centred so that LayerNorm over the wider stream gives the same result. TinyLlama-1.1B, Qwen2.5-0.5B, SmolLM2-360M and SmolLM2-135M all run on one interpreter written for the largest shape among them (802 layers, width 84,042).

更小的模型可以放进按更大形状写的解释器：用零补齐。缺的层、头和神经元都是零，残差向量先去均值，使更宽的残差流上的 LayerNorm 给出同样的结果。TinyLlama-1.1B、Qwen2.5-0.5B、SmolLM2-360M 和 SmolLM2-135M 都在同一个解释器上运行，它按其中最大的形状来写（802 层，宽 84,042）。

An interpreter in the prompt of another interpreter把解释器放进另一个解释器的 prompt

The interpreter is itself a GPT-2-family transformer, so its weights can be the prompt of a second interpreter written for its shape. We trained a character model on TinyStories and ran it two levels deep.

解释器本身是 GPT-2 家族的 transformer，所以它的权重可以作为第二个解释器的 prompt，后者按它的形状来写。我们在 TinyStories 上训练了一个字符模型，让它在两层嵌套里运行。

Limits局限

  • The interpreter is larger than the model it runs. It carries that model's residual stream inside its own, so it is several times wider, and it spends 6 of its layers (GPT-2 family) or 25 (Llama family) on each layer of that model. A small interpreter that runs a large model in many steps, writing intermediate results back into its context, would be a different construction; we have not built it.解释器比它运行的模型大。它把那个模型的残差流带在自己的残差流里，所以宽度是那个模型的好几倍；那个模型的每一层要用掉它的 6 层（GPT-2 家族）或 25 层（Llama 家族）。用一个小解释器分很多步运行大模型、把中间结果写回上下文，是另一种构造，我们还没有做。
  • Speed. The interpreter writes a token of GPT-2 XL in about 2 seconds on two B200 GPUs, after 71 seconds to prepare the prompt. Running GPT-2 XL directly is far faster. The interpreter's own weights, stored densely, would be 4.9 trillion numbers, nearly all of them zero.速度。解释器在两张 B200 上写出 GPT-2 XL 的一个 token 约需 2 秒，此前要用 71 秒准备 prompt。直接运行 GPT-2 XL 快得多。解释器自己的权重若稠密存储是 4.9 万亿个数，几乎全是零。
  • Float64. The construction spends several digits in cancellations. Evaluated in float32, the same weights reach 3×10−6 (GPT-2 family) and 10−4 (Llama family) on small random models.需要 float64。构造在几处相消里要用掉好几位有效数字。同样的权重用 float32 计算时，在小的随机模型上只能到 3×10−6（GPT-2 家族）和 10−4（Llama 家族）。
  • Sampling needs a small vocabulary. When the vocabulary is wider than the interpreter, its last head points at the top token of the model in the prompt, so generation is greedy. With a small vocabulary the interpreter outputs all the logits and can be sampled, as in the drawing experiment.采样需要小词表。词表比解释器还宽时，解释器最后一个头指向 prompt 里的模型概率最高的那个 token，所以生成是贪心的。词表小的时候解释器输出全部 logits，可以采样，画画的实验就是这样。
  • A calibration pass. The loader scales each matrix row by its largest value on four short TinyStories texts, much like the calibration step of quantization.一次校准。加载器按每个矩阵行在四段 TinyStories 短文上的最大值给它定尺度，类似量化里的校准步骤。
  • Architectures covered. The GPT-2 family (LayerNorm, learned positions, tanh-GELU) and the Llama family (RMSNorm, rotary positions, grouped-query attention, SwiGLU; Qwen2's biases too). Still open: exact erf-GELU, per-head q/k normalization (Qwen3), mixture-of-experts routing, sliding-window attention.支持的架构。GPT-2 家族（LayerNorm、学习的位置嵌入、tanh 版 GELU）和 Llama 家族（RMSNorm、旋转位置编码、分组查询注意力、SwiGLU；也支持 Qwen2 的偏置）。尚未支持：精确的 erf 版 GELU、按头的 q/k 归一化（Qwen3）、混合专家路由、滑动窗口注意力。

One failure is worth showing. The construction's errors are absolute: about 10−12 of the largest value a quantity takes at any position. That fails where a model is extremely sensitive to a value that is tiny, and TinyLlama's beginning-of-text token is such a place. Its residual vector has norm 10−11 in the first layers, so RMSNorm, dominated by its epsilon, multiplies it by 316; the model amplifies a perturbation there about 20 times per layer, and every position attends to that token. With the token, the logit error is 10−2 (float32 inference: 3×10−4) and the next tokens still all match. Without it, the error stays at 10−11 through every layer (Figure 6). Llama-3.2-1B runs with its beginning-of-text token at 2×10−9, so this is particular to TinyLlama.

有一处失败值得展示。构造的误差是绝对误差：约为某个量在所有位置上最大值的 10−12。如果模型对一个极小的数值极其敏感，这就会出问题，TinyLlama 的开头 token 正是这样的地方。它的残差向量在前几层范数只有 10−11，RMSNorm 被 epsilon 主导，等于把它放大 316 倍；模型在这里每层把扰动放大约 20 倍，而所有位置都在注意这个 token。带上它时 logits 误差是 10−2（float32 推理：3×10−4），下一个 token 仍然全部一致；去掉它，误差在每一层都保持在 10−11（图 6）。Llama-3.2-1B 带着自己的开头 token 运行，误差是 2×10−9，所以这个问题是 TinyLlama 特有的。

How it was built是怎么做出来的

The interpreter's weights come from a program that Claude wrote: Fable 5.2 wrote the GPT-2-family interpreter (about 600 lines of Python), the padding and the three-level tower; Opus 5.5 wrote the Llama-family construction. We set the goals (a real model rather than a toy, then one interpreter for every size, then Llama with an exact SiLU) and asked questions. Claude designed the construction, wrote the code, ran the experiments on GPUs, and found its own bugs by comparing the interpreter's intermediate values, layer by layer, with those of the model in the prompt.

解释器的权重来自 Claude 写的程序：Fable 5.2 写了 GPT-2 家族的解释器（约 600 行 Python）、补零和三层嵌套；Opus 5.5 写了 Llama 家族的构造。我们定目标（先是要跑真实模型而不是玩具，然后是一个解释器跑所有尺寸，再然后是用精确的 SiLU 跑 Llama）并提问。Claude 设计构造、写代码、在 GPU 上跑实验，并且通过逐层比对解释器的中间值和 prompt 里那个模型的值来自己找 bug。

Three of those bugs are worth telling, because each one looked like a precision limit and turned out to be a mistake. An offset was added to the same weight row as a mask of size 1024 and disappeared in the sum, which broke a width-64 tower until the offset moved to its own row. A clearing step ran in a layer where the interpreter's LayerNorm was not linear and wrote 10−8 of garbage where zero was meant. And the first token of a TinyLlama text forms an activation 101 times larger than anything in the calibration text, which a smaller linearization step absorbed.

其中三个 bug 值得一提，因为它们看起来都像精度极限，结果都是写错了。一个偏移量和一个 1024 的 mask 加在同一行权重上，在求和中被吃掉了，导致宽 64 的嵌套失败，直到把偏移量挪到单独一行。一个清零步骤被放在了解释器的 LayerNorm 不是线性的那一层里，本该写零的地方写进了 10−8 的垃圾。还有，TinyLlama 文本的第一个 token 会形成比校准文本里任何值都大 101 倍的激活，用更小的线性化步长才把它吸收掉。
